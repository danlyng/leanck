# CLAUDE.md

## Project

leanck provides standalone Lean 4 tooling through a CLI and an MCP server. Read `README.md` and `packaging/plugin/README.md` for setup and the component map.

## Build and test

- `just build` stages the unified `leanck` executable into `plugin/bin/` and installs it on PATH.
- `just package-plugin` builds locked release binaries and assembles the Claude Code and Codex plugin into the ignored, generated `leanck-plugin/`; `just validate-plugin` runs `claude plugin validate --strict` on it. `just install-cli` installs `leanck`, which the Codex plugin launches from PATH with `serve mcp`.
- `cargo build --release --workspace --locked` builds every binary.
- `cargo test --workspace --locked` runs the Rust suite.
- `just build-plugin-bin` stages the unified binary. On macOS, copies must be re-signed ad hoc; the recipes already do this.
- Live tests need Lake. Set `LEANCKD_TEST_PROJECT` to an absolute path to a disposable copy of `crates/leanck-mcp/test-project`, then run `cargo test -p leanckd --lib live_smoke --locked -- --ignored` and `cargo test -p leanckd --test socket_smoke --locked -- --ignored` sequentially. The MCP client test is `cargo test -p leanck-mcp --test daemon_e2e --locked -- --ignored`; build the workspace first so the test can select the built `leanck` beside the test executables.

`just stage /absolute/staging/directory` builds locked release artifacts and signs copied macOS executables without installing them. `just verify-distribution /absolute/template/project` uses temporary staging and unique disposable workspaces to check discovery, concurrent clients, switching, signing, and shutdown. The in-process live engine test uses `--lib live_smoke`; socket and MCP tests remain integration targets.

## Source map

- `leanck-cli/src/cli.rs`: user command surface. `serve.rs` dispatches `serve mcp` and `serve daemon` with mode-specific runtime/logging; executable lifecycle and MCP stdio tests live in `leanck-cli/tests/`. `args.rs` holds shared workspace, timeout, and output flags. Live queries use `leanck-client`; builds use `leanck-lake`; normalization uses `leanck-normalize::command`; `doctor` is a non-spawning probe; `daemons` lists and stops daemons machine-wide through `leanck_client::instances`.
- `leanck-mcp/src/mcp.rs`: MCP tool definitions and error adaptation. `workspace.rs` holds the selected client and host-executable fallback; each operation captures one immutable shared client. `set_workspace` needs only a Lake marker.
- `leanck-client`: shared workspace-bound client, discovery, startup, validated transport, retry policy, and live-query rendering. Public operations accept exact core parameter types and return exact core result types. Timeouts are supplied per request. Only failed connections permit a retry; failed writes, reads, or protocol validation are never automatically replayed.
- `leanck-core`: shared identity, runtime paths, typed operation/parameter pairing, version 4 request/result models and wire errors, and optional Tokio length-delimited private-socket framing through its `wire` feature. Pagination counts use u64; diagnostic severity keeps its numeric wire representation through a domain enum. `ListParams.kind` is `Option<Vec<KindSelector>>` (omitted/empty means all); `ListedSymbol.kind` is a source-tagged `DeclarationKind`, not a string. Selectors are closed snake_case names; lexical Lean kinds take priority over coarse LSP fallbacks.
- `leanckd`: Unix socket service and workspace lifecycle. Only `run`, `run_with_settings`, `run_with_runtime_directory`, and their error/result types are public; live engine tests are compiled inside the library. `documents.rs` owns canonical source/version leases, all document mutations, import freshness, and retention; `state/` owns ElaborationStore generation/version transitions; `query.rs` owns QueryService; `declarations.rs` shares LSP/lexical discovery across listing and lookup; `scan.rs` provides UTF-16-aware heuristic tokens. `server/session.rs` owns typed standard LSP operations and Lean extensions; `server/io.rs` adapts lsp-server messages/request queues to cancellable child I/O. The unified CLI calls its public runner; query frontends still communicate only through `leanck-client`. Daemon startup consumes cache outcomes from `leanck-lake` and chooses best-effort recovery.
- `leanck-lake`: bounded project-toolchain execution and cross-process build/cache coordination, build parsing/rendering and outcomes, Mathlib cache detection/fetching, and evaluated project source-root discovery through `lake env printenv LEAN_SRC_PATH`. Uses the project's own `lake` on PATH. The crate is a library; it does not stage a replacement Lake binary.
- `leanck-loogle`: shared structured search client with a reusable HTTP pool, endpoint fallback, limits, empty-query/multiple-term policy, and endpoint provenance. `loogle.endpoints` configures the local/main fallback list. Coverage is not inferred from URLs.
- `leanck-normalize`: pure `normalize` API with options, output, statistics, and explicit copyright year. The optional `command` module backs both binary entry points. Default features include the command adapter; library-only consumers can disable default features.
- `markdown-reflow`: Git dependency from `https://github.com/danlyng/markdown-reflow`, pinned by revision in `leanck-normalize/Cargo.toml`. Update it with `cargo add -p leanck-normalize markdown-reflow --git https://github.com/danlyng/markdown-reflow.git --rev <COMMIT>` and rerun the normalizer tests.
- `packaging/plugin/`: plugin manifests, Claude/Codex MCP configs, and the plugin README, copied verbatim into the package. `packaging/package_plugin.py` adds `leanck-skills/`, `leanck-subagents/` (`*.md` for Claude Code, `*.codex.toml` for Codex under `codex/agents/`), `leanck-hooks/`, and staged binaries, validating frontmatter, TOML, and JSON first. `plugin/` is a legacy copy kept for reference; do not edit it.
- `leanck-hooks/`: plugin hooks shared by Claude Code and Codex.
- `leanck-skills/`, `leanck-subagents/`: CLI-oriented workflow definitions.
- `test-support/contracts/v4.json`: authoritative version 4 contract fixtures, consumed directly rather than patching version 1 fixtures.

## Runtime

The daemon warms the project before binding its socket. For Mathlib projects, it attempts `lake exe cache get` first (best effort; `cache.enabled=false` skips it). The shared client waits while the daemon is alive, up to its startup cap. Socket, pid, and lock paths are derived per worktree.

`[instances]` caps daemons machine-wide (`leanck-core/src/instances.rs`). After its worktree lock, each daemon holds an exclusive lock on the lowest free `leanck-slot-N.lock` in the selected runtime directory, recording pid, canonical worktree, socket, and start time; counting and listing read records and never lock or create the directory. Admission holds `leanck-slots.lock` in canonical order across existing candidate directories while it takes a slot and counts the other held slot locks against the limit, so the slot index is not the count. A record is live only while its pid is alive and that process has the recorded `start_id` (`process_start_id`: start time at fork on macOS, ticks since boot on Linux, so a wall-clock step cannot change it), so a crashed daemon's record does not count once its pid is reused; records without one fall back to comparing the process start time with `started_at` plus a few seconds of slack. A daemon refused by the limit exits 75 (`EXIT_INSTANCE_LIMIT`); every new daemon, including temporary fallbacks, holds a slot. Runtime selection prefers valid `$XDG_RUNTIME_DIR/leanck`, then the effective cache directory, then private `leanck-<uid>` directories under the system temporary directory and `/tmp`. Validate socket byte length, ownership/permissions, file creation, locking, and socket binding before Lean warmup. Clients explicitly pass `--runtime-dir` to pin the selected location. Discovery follows held lifetime locks across candidates; these locks record the selected directory and are never unlinked while owned. The daemon never evicts: under `evict_idle`, the client (`leanck-client/src/startup.rs`, `instances.rs`) stops as many of the longest-idle ready daemons over their sockets as one more daemon needs and retries the spawn. Clients starting the same worktree take turns on its `leanck-<key>.start.lock`, so concurrent cold starts make room once; an evicted daemon that accepted the stop but has not exited is waited for and never replaced by another eviction. Eviction and `leanck daemons stop --idle` send `shutdown` with `if_idle`: the daemon checks for queued or running work and closes admission in one step (`leanckd/src/activity.rs`), answering `shutting_down: false` when busy, so neither ever cancels admitted work; the idle reaper uses the same check, and a query refused after admission closes gets `server_down`. Control operations (`health`, `status`, `cancel`, `shutdown`) never touch the idle clock, so probing or listing a daemon neither postpones its idle shutdown nor hides how long it has been idle. `leanck daemons` lists and stops daemons from slot records; the MCP `health` payload carries the same `instances` summary. The project `leanck.toml` cannot set `[instances]`. Tests that start daemons must isolate `XDG_RUNTIME_DIR`, `XDG_CACHE_HOME`, and `TMPDIR` or pass `--set instances.limit=0`, or they count against and may evict the developer's real daemons; the ignored live tests use the real cache directory with the default policy.

Normal client queries negotiate wire version 4 through health before dispatch. Upgrade clients and daemon together and explicitly shut down older daemons; incompatible peers are not translated. Cold startup, operation execution, and short probes have separate budgets; `RequestOptions::transport_timeout_ms` independently bounds socket I/O. Request cancellation and dropped futures retain the query ID for a bounded best-effort cancel, and connection loss also cancels daemon work. The mandatory lifetime lock remains on disk after shutdown; ownership is released by closing its descriptor, including on crash. Do not unlink the lock while a daemon owns it.

Builds use the project's own `lake` on PATH, preserving toolchain compatibility with the Lean language server. Execution, parsing, and rendering are shared in `leanck-lake`. Requested warnings include dependency diagnostics and locationless configuration warnings; strict mode rejects recognized warnings, including with a zero Lake exit code.

The daemon is the single shared owner of the Lean server, which is what fixes the multi-agent deadlocks the HTTP-to-VSCode path had: one absolute request deadline and cancellation token cover admission, document locks, elaboration, confirmation, enrichment, and LSP requests; dropping a pending LSP future emits `$/cancelRequest`; agents waiting on the same file share one elaboration wait (`tokio::Notify` per URI); sync, restarts, and recovery share a per-URI read/write lock; query leases pin source/version/session and block mutation; generation-bound notifications reject obsolete state; a semaphore caps in-flight elaboration work; and ElaborationStore uses `std::sync::Mutex` so state guards cannot cross `.await` in the spawned query tasks. Document read/write leases intentionally span asynchronous work. Socket, PID, and lock paths are derived per worktree in `leanck-core/src/paths.rs`; `leanck-core/src/api.rs` and `wire.rs` are shared with the client. Connection, supervision, Lean I/O, and stderr tasks are tracked and stopped during bounded shutdown. Idle accounting uses monotonic time and includes queued/running operations. `HealthResult.lifecycle` is mandatory and reports ready, recovering, or shutting_down state and active request count.

## Packaging

`plugin/bin/` contains staged executables, not source. The CLI/MCP supply their own executable to the shared client; configured `client.daemon_bin` takes precedence, and other library hosts fall back to sibling/PATH discovery of `leanck`. Auto-start launches use `serve daemon WORKTREE --runtime-dir DIRECTORY --no-config` plus resolved settings. Auto-start sets `argv[0]` to `leanckd`, but admission, discovery of running instances, eviction, and stopping use slots/PIDs/start identities/sockets and never process names. The former `leanckd` and `leanck-mcp` binary targets are removed; the crates remain libraries. The core has no credential or database bootstrap step. Normalization uses `leanck normalize [OPTIONS] [PATH]` or standalone `leanck-normalize [OPTIONS] [PATH]`. Set width only with `--width N`; a numeric positional argument is a path. CLI file restarts use `leanck restart-file <file>`; MCP keeps `restart_file`. MCP `sorry` accepts `path`, not the former `file` alias.

The Lean transport uses lsp-server 0.10 and lsp-types 0.95.1 models. LeanSession handles supported server requests explicitly and returns method_not_found for unsupported ones. One blocking parser task uses SyncIoBridge over a cancellation-aware reader; the writer stays asynchronous. Query handlers call typed session operations rather than constructing LSP method strings/JSON. Private socket framed readers must live for the connection lifetime so read-ahead bytes are retained; reads/writes share a 16 MiB cap and truncated frames fail.

Document retention targets 128 entries and 64 MiB of source, with active leases and queued operations protected. Eviction sends didClose and forgets state; versions are not reused during the daemon lifetime. Source-root discovery is bounded to five seconds; unresolved layouts reopen conservatively. Directory sorry scans are text-only and do not open documents. Sorry reports always carry quality notes; `SorryParams` accepts only `path`, with no notes opt-in. List/reference fallbacks also expose quality notes. `DiagnosticsResult.source` is a mandatory pinned `String`; excerpts never fall back to the filesystem. See `docs/refactor/STAGE_7.md`.

Builds remain outside daemon RPC. `leanck-lake` owns their default 30-minute budget, 8 MiB per-stream capture limit, cancellation, process-group cleanup, and JSON provenance. CLI exposes `--timeout SECS` and `--max-output-bytes BYTES`; MCP exposes `timeout_ms`, `max_output_bytes`, and optional targets. Build/cache entry points share the stable `.lake/leanck-execution.lock`; canonical aliases share ownership, and the child inherits the descriptor so it retains the lease after a caller crash. Keep that inode while owned. External Lake commands and Lean internal dependency builds retain their normal behavior. Generic read-only Lake probes avoid this gate. CacheOptions.execution supplies the shared runner settings (20-minute default for cache). File locking requires Rust 1.89 or newer. See `docs/refactor/STAGE_8.md`.
