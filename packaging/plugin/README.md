# leanck plugin

Lean 4 proof tools for Claude Code and Codex: live diagnostics, proof goals, unfinished proofs, declaration lists, builds, Loogle search, and source normalization through the `leanck` CLI and the `leanck serve mcp` server, plus proof and style skills, subagents, and a `push_neg` migration hook.

This directory is generated by `just package-plugin` or release packaging from the leanck repository. Do not edit it; change the sources and repackage. `.leanck-package.json` records the source commit.

For prebuilt installation, use the repository's `install.sh`. Plugin mode is selected by default and includes both host forms, skills, custom agents, hooks, and MCP under `~/.local/share/leanck`. The installer registers a local `leanck-installer` marketplace with detected hosts; `--plugin claude`, `--plugin codex`, or `--all` selects hosts explicitly. It installs `bin/leanck` under the data directory, pins that absolute path in `.mcp.codex.json`, and links the included Codex agents from the data directory into `~/.codex/agents/leanck/` (honoring `CODEX_HOME`). The final Cancel / Continue / Edit advanced config... prompt defaults to Cancel. Advanced settings are edited in place: Up and Down select a field, Enter cycles settings with fixed choices, and Left and Right cycle backward and forward. Enter on a path edits or saves its text, and Escape discards the current text edit. Skills and Claude agents are marked `[bundled with plugin]`, Codex agents show their destination, and additional skill and agent locations can be added. Shell completions support Bash, Zsh, Fish, PowerShell, and Elvish with editable destinations. Shell and profile fields appear only when Add leanck to PATH is enabled; installer state and timeout are available through flags. Save changes applies the draft and returns to the final prompt. Cancel discards the draft, asking for confirmation if settings have changed. Use `--yes` for noninteractive approval, `--force` to back up and replace conflicts, or `--dry-run` to preview. The commands below describe manual installation from source.

## Claude Code

The plugin is self-contained. Claude Code puts `bin/` on the Bash tool's PATH, so skills and agents can run `leanck`, and `.mcp.json` starts `bin/leanck serve mcp`; it starts the same executable in `serve daemon` mode as needed. Try it from a Lean project with:

```sh
claude --plugin-dir /path/to/leanck/leanck-plugin
```

## Codex

Codex does not put plugin executables on PATH. The installer pins the MCP command to its installed executable, so MCP does not depend on PATH. For manual installation from source, the packaged configuration uses `leanck` from PATH; install the executable first from the leanck repository:

```sh
just install-cli
```

The installer includes Codex custom agents automatically. For manual installation, copy them into `${CODEX_HOME:-~/.codex}/agents/leanck/` (personal) or a project's `.codex/agents/leanck/`:

```sh
mkdir -p "${CODEX_HOME:-$HOME/.codex}/agents/leanck"
cp codex/agents/*.toml "${CODEX_HOME:-$HOME/.codex}/agents/leanck/"
```

Codex does not trust plugin hooks automatically. Review and trust the hook with `/hooks`.

## Runtime

The MCP server and CLI start one shared `leanck serve daemon` process per worktree; it runs the project's own `lake serve`, so no editor is needed. A Lean toolchain and Lake must be available through elan in the project. See the repository README and `docs/CONFIGURATION.md` for configuration, and `crates/leanck-mcp/README.md` for the MCP tool reference.
