# leanck plugin

Lean 4 proof tools for Claude Code and Codex: live diagnostics, proof goals, unfinished proofs, declaration lists, builds, Loogle search, and source normalization through the `leanck` CLI and the `leanck serve mcp` server, plus proof and style skills, subagents, and a `push_neg` migration hook.

The `leanck` skill provides a minimal command reference. The `lean-proving` and `lean-style` skills provide opinionated workflows.

Plugin installation bundles the CLI, all skills, custom agents, and hooks, with optional MCP. A la carte installation (`--standalone`) lets you choose the CLI, individual skills, and custom agents without registering a plugin or installing hooks. Interactive setup describes each skill and lets you include or skip it; advanced settings provide individual skill toggles. For automation, `--skills HOST` selects the destination hosts and repeatable `--skill NAME` selects skills (`all` by default, or `none`). For example, `--standalone --skills both --skill leanck` installs the CLI and only the minimal reference skill for both hosts. Skill choices are saved for later installer runs and apply to additional skill locations too; omitted skills already on disk are preserved.

This directory is generated by `just package-plugin` or release packaging from the leanck repository. Do not edit it; change the sources and repackage. `.leanck-package.json` records the source commit.

Plugin installation prompts for shell completions, defaulting to the current supported shell from `SHELL` or `none` if detection fails or the shell is unsupported. Saved choices and explicit flags override the completion default. It also prompts to add `leanck` to PATH, defaulting to yes. Completion directories and shell profiles use their defaults without prompting and can be changed in advanced settings. If the selected completions directory or shell profile is missing, the installer warns and skips that update without creating it. These warnings appear at every confirmation and refresh after advanced settings change. Use `--completions none` and `--no-add-to-path` to disable these changes in automation. If PATH setup is disabled, the installer warns that agents may not be able to execute `leanck`.

For prebuilt installation, use the repository's `install.sh`. Plugin mode is selected by default and includes both host forms, skills, custom agents, and hooks under `~/.local/share/leanck`. The installer registers a local `leanck` marketplace with detected hosts; `--plugin claude`, `--plugin codex`, or `--all` selects hosts explicitly. It installs `bin/leanck` under the data directory, pins that absolute path in the Codex MCP definition, and links the included Codex agents from the data directory into `~/.codex/agents/leanck/` (honoring `CODEX_HOME`). MCP defaults to off. Enable it with **Enable MCP** in advanced config or `--mcp`; `--no-mcp` disables a remembered choice. Disabled definitions are saved as `.mcp.disabled.json` and `.mcp.codex.disabled.json`, and the Codex manifest omits its MCP reference. Saved MCP choices are reused. The final Cancel / Continue / Edit advanced config... prompt defaults to Cancel. Advanced settings are edited in place: Up and Down select a field, Enter cycles settings with fixed choices, and Left and Right cycle backward and forward. Enter on a path edits or saves its text, and Escape discards the current text edit. Skills and Claude agents are marked `[bundled with plugin]`, Codex agents show their destination, and additional skill and agent locations can be added. Shell completions support Bash, Zsh, Fish, PowerShell, and Elvish with editable destinations. Shell and profile fields appear only when Add leanck to PATH is enabled; installer state and timeout are available through flags. Save changes applies the draft and returns to the final prompt. Cancel discards the draft, asking for confirmation if settings have changed. Use `--yes` for noninteractive approval, `--force` to back up and replace conflicts, or `--dry-run` to preview. Use `sh ./install.sh --from-repo .` from the repository root to build and install a local checkout through the same flow (Rust/Cargo required); adding `--dry-run` previews without building. The commands below describe manual installation from source.

To uninstall an installer-managed copy, run the standalone `uninstall.sh` from the repository or extracted release archive. Use `--dry-run` to preview, `--yes` for noninteractive approval, and `--state-dir DIR` for a custom installer state location. It unregisters recorded host plugins, stops daemons, removes unchanged managed components and PATH blocks, and preserves edited files, user configuration, and installer backups.

## Claude Code

The plugin is self-contained. Claude Code puts `bin/` on the Bash tool's PATH, so skills and agents can run `leanck`, and `.mcp.json` starts `bin/leanck serve mcp`; it starts the same executable in `serve daemon` mode as needed. Try it from a Lean project with:

```sh
claude --plugin-dir /path/to/leanck/leanck-plugin
```

## Codex

Codex does not put plugin executables on PATH. The installer pins the MCP command to its installed executable, so MCP does not depend on PATH. For manual installation from source, the packaged configuration uses `leanck` from PATH; install the executable first from the leanck repository:

```sh
just install-cli
```

The installer includes Codex custom agents automatically. For manual installation, copy them into `${CODEX_HOME:-~/.codex}/agents/leanck/` (personal) or a project's `.codex/agents/leanck/`:

```sh
mkdir -p "${CODEX_HOME:-$HOME/.codex}/agents/leanck"
cp codex/agents/*.toml "${CODEX_HOME:-$HOME/.codex}/agents/leanck/"
```

Codex does not trust plugin hooks automatically. Review and trust the hook with `/hooks`.

## Runtime

The MCP `doctor` tool checks the workspace without starting Lean and reports available leanck updates. Existing MCP `health` also reports updates while retaining its daemon-start behavior. Both keep cached notices visible between daily foreground checks unless user configuration sets `[updates].check = false`. MCP startup and ordinary proof queries do not check for updates.

Installer-managed plugins can be updated with `leanck update --dry-run`, then `leanck update` (or `--yes --json` for automation). The native Rust updater preserves the installed MCP setting, plugin, skills, agents, completions, custom destinations, and selected host registrations. It verifies the release and retains recoverable backups. Active MCP, CLI, and daemon sessions defer installation; stop them before applying an update and restart agent hosts afterward. A partial host refresh can be retried with `leanck update --retry-registration --yes`. Opt-in `[updates].auto_install = true` applies updates on later eligible CLI launches when no session is using the installation. Source builds use the source installation workflow.

The MCP server and CLI start one shared `leanck serve daemon` process per worktree; it runs the project's own `lake serve`, so no editor is needed. A Lean toolchain and Lake must be available through elan in the project. See the repository README and `docs/CONFIGURATION.md` for configuration, and `crates/leanck-mcp/README.md` for the MCP tool reference.
