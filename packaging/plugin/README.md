# leanck plugin

Lean 4 proof tools for Claude Code and Codex: live diagnostics, proof goals, unfinished proofs, declaration lists, builds, Loogle search, and source normalization through the `leanck` CLI and the `leanck-mcp` server, plus proof and style skills, subagents, and a `push_neg` migration hook.

This directory is generated by `just package-plugin` from the leanck repository. Do not edit it; change the sources and repackage. `.leanck-package.json` records the source commit.

## Claude Code

The plugin is self-contained. Claude Code puts `bin/` on the Bash tool's PATH, so skills and agents can run `leanck`, and `.mcp.json` starts `bin/leanck-mcp`, which finds `bin/leanckd` beside it. Try it from a Lean project with:

```sh
claude --plugin-dir /path/to/leanck/leanck-plugin
```

## Codex

Codex does not put plugin executables on PATH, and it starts plugin MCP servers either in the plugin directory or in the session directory. `leanck-mcp` takes its workspace from its working directory, so the Codex configuration launches the PATH copy in the session directory. Install the executables first, from the leanck repository:

```sh
just install-cli
```

Codex plugins cannot register custom agents. To enable the agents, copy them into `~/.codex/agents/` (personal) or a project's `.codex/agents/`:

```sh
cp codex/agents/*.toml ~/.codex/agents/
```

Codex does not trust plugin hooks automatically. Review and trust the hook with `/hooks`.

## Runtime

The MCP server and CLI start one shared `leanckd` daemon per worktree; it runs the project's own `lake serve`, so no editor is needed. A Lean toolchain and Lake must be available through elan in the project. See the repository README and `docs/CONFIGURATION.md` for configuration, and `crates/leanck-mcp/README.md` for the MCP tool reference.
